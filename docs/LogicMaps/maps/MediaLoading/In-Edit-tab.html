Edit state restoration during publication
PEditCropRestore does not use the LCargo passed to the event; it restores source-specific and carried crop/edit state from the viewer's current PViewerSourcePath and crop state at the moment this subscriber runs
edit.PEditCropRestore(...)property viewer.PViewerSourcePath
Successful Flyleaf/mpv commits assign PViewerSourcePath before PViewerMediaRaise, so restoration then targets the newly committed source before those commit methods continue into preview restoration, autoplay/pause, and final playback-state updates.
Backend load failure is different: PViewerLoadHandle raises a failure cargo without replacing PViewerSourcePath, so Edit restores against the previously committed source, if any. Viewer close clears PViewerSourcePath before publishing its empty cargo.
